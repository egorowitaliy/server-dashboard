# Модель безопасности

## Назначение

Server Dashboard предназначен для внутренней административной сети. Публичная доступность исходного кода не означает, что веб-интерфейс следует открывать в Интернет.

## Разделение привилегий

PHP-FPM работает от `server-dashboard-web`. Команды, требующие повышенных прав, выполняет отдельная служба от `root`. Веб-часть обращается к ней через Unix-сокет и передаёт имя заранее зарегистрированной операции и проверенные параметры.

Пользовательский ввод не используется как произвольная команда оболочки, путь к программе или свободный набор аргументов.

## Ограничение административных действий

- перезапуск службы разрешается только при `restart = true` у этой службы;
- перезапуск контейнера разрешается только для имён из `docker.restart_allow`;
- снятие блокировки Fail2Ban разрешается только для jail из `fail2ban.unban_allow`;
- выключение и перезагрузка требуют отдельного подтверждения в интерфейсе;
- изменяющие запросы проходят CSRF-проверку и записываются в журнал.

## Вход

Веб-часть использует cookie с `HttpOnly` и `SameSite=Strict`. Сессии хранятся в отдельном каталоге `/run/server-dashboard/sessions`.

После нескольких неудачных попыток входа адрес временно блокируется приложением. Во время блокировки форма входа не выдаётся, а проверка блокировки выполняется до проверки пароля. Старые файлы сессий и ограничителя очищаются через tmpfiles.

## Nginx

Пример конфигурации:

- ограничивает доступ заданной внутренней сетью;
- запрещает прямой запуск произвольных `.php`;
- добавляет основные защитные заголовки;
- использует отдельный адрес `/api/action` для длительных изменяющих операций.

Если сеть нельзя считать доверенной, включите HTTPS. Обычный HTTP допустим только внутри действительно изолированной локальной сети.

## Локальная документация

Раздел документации работает только на чтение. При открытии файла проверяются:

- допустимое расширение;
- отсутствие `..` и абсолютного пути;
- нахождение результата внутри заданного корневого каталога;
- отсутствие выхода наружу через символическую ссылку;
- запрет скрытых компонентов пути.

Сырой HTML из Markdown не выполняется, а опасные схемы ссылок не превращаются в активные ссылки.

## Внешние модули

Серверная часть внешнего модуля выполняется внутри привилегированной службы и поэтому должна считаться доверенным кодом.

Перед загрузкой проверяются владелец, права, родительские каталоги, описание модуля и объявленные статические файлы. Внешний модуль не может зарегистрировать операцию от имени другого модуля или занять идентификатор встроенной страницы.

Не устанавливайте внешние модули из неизвестного источника и не ослабляйте ограничения systemd-службы ради одного модуля. Если функции модуля нужен отдельный сетевой доступ или необычные полномочия, лучше вынести такую часть в отдельную службу с собственными правами.

## Секреты

`/etc/server-dashboard/secrets.ini` не должен попадать в систему контроля версий, резервные публичные архивы или сообщения об ошибках. Права файла должны позволять чтение только `root` и веб-группе.
